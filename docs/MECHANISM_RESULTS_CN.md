# 机制计算结果工作台

在侧栏选择项目，进入“机制计算”。完成并同步回本机的生产批次会显示在页面顶部，装配、平衡和早期准备记录仍保留在下方。

## 查看与导出

- **候选与重复比较**：按水、乙醇或其他已分析分子切换结果。图中每个点代表一条独立重复轨迹；先在轨迹内部平均各位点，再汇总重复。亚基不单独增加样本数。
- **逐位点结果**：保留每个亚基的分子占据、进入次数、驻留事件和通道采样结果。轨迹开始前已进入或结束时尚未离开的驻留事件单独计数；中位时长仅使用完整观察到的事件。
- **轨迹质检**：分别显示分析是否覆盖预定的全部位点、质检状态、核心 Cα RMSD 和发现的问题。没有质检报告的轨迹显示“尚未质检”，任务完成状态不会自动变成质检通过。
- **报告下载**：可下载候选比较、逐重复、逐位点和质检 CSV，以及原始批次分析、完整结构质检 JSON。CSV 使用 UTF-8 BOM，可直接在中文 Excel 中打开。

未找到通道的采样帧不按零瓶颈参与均值。表中最小值和最大值表示重复间范围；这些描述量不转换为酶活、合成/水解比或可靠转移速率。位点半径或生产时长不一致的结果须分别比较。

## 结果来源检查

新批次在每条轨迹记录中保留 `expected_regions`。早期批次可通过与冻结批次校验值一致的补充记录提供预定位点清单。缺少预定清单时，工作台不将分析标记为完整。

本机项目索引可关联以下补充记录，路径及研究数据均留在研究工作区：

| 记录类型 | 必需字段 | 用途 |
|---|---|---|
| `mechanism_quality` | `task_id`、`report_path`、`sha256` | 关联生产轨迹质检 |
| `structure_batch_review` | `report_path`、`sha256` | 显示完整构建的结构复核 |

质检报告须提供冻结批次的 SHA-256，并逐条记录对应 `trajectory_report.json` 的 SHA-256。读取时核对这些文件；记录发生变化时显示错误，不能沿用旧的通过状态。早期批次的预定位点补充字段为 `expected_regions` 和 `batch_manifest_sha256`。

软件测试覆盖位点与重复的分组、缺失分析、质检缺失与失败、驻留截断、无通道结果、比较尺度及文件一致性。真实结构和轨迹的验收记录保存在各研究项目内，软件测试不替代机制采样评估。
