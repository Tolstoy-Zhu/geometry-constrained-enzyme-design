# 通道参数、采样与平台验收

在已有“机制计算”结果区增加“通道参数检查”和“机制采样评估”，在“项目与任务”显示“平台整体验收”。评估只读取已有生产轨迹，不增加生产模拟时长。原始批次、轨迹及早期失败记录保留。

## 通道参数检查

默认协议在计算前固定并写入 `assessment_identity.json`：

| 参数 | 默认设置 |
|---|---|
| 网格间距 | 0.6、0.8、1.0 Å |
| 探针半径 | 1.0、1.2、1.4、1.8 Å |
| 网格起点 | 原起点及三轴同时偏移半个网格 |
| 采样帧 | 每 100 帧一次，并包含最后一帧 |
| 几何算法 | 蛋白原子表面间隙网格，六邻接最宽路径；v2 在搜索时计入整段边的间隙 |
| 路径检查 | 逐线段计算到原子范德华球面的最小间隙 |
| 网格差异筛查 | 路径有效性不一致帧比例 >0.1，或共同有路径帧的最大瓶颈差 >0.3 Å |

在每一帧先完成蛋白成键连续化，再将各亚基放到同一周期映像。两个亚基分别计算。相同网格用于不同探针与位点，避免重复构建距离场。v1 原算法的诊断报告中，网格点通畅但点间线段碰撞时记录“需复核”。v2 搜索时直接排除间隙不足的边，并对最终路径再次独立核查。修正版单独运行和保存，原报告保留。

上述差异阈值是本工程预览的筛查规则，不是普适的通道收敛标准。不同探针表示不同几何条件，不要求它们给出相同开放率；这些半径尚未标定为特定底物尺寸。未找到路径的帧不赋零瓶颈，也不能据此断言物理通道关闭。每个构建仍只有实际独立重复数，网格设置、帧和亚基不增加独立样本数。

## 占据采样诊断

对每个“构建 × 位点 × 分子”分别诊断，状态定义固定为：0 表示位点中无该分子标记原子，1 表示至少存在一个。所有转移计数限定在同一重复轨迹内，不能跨重复连接。

- 滞后帧数：1、2、5、10、20、50；时间单位使用轨迹实际采样间隔。
- 基准滞后：5 帧；时间尺度平台检查使用 5、10、20 帧。
- 最少 3 次独立重复；每次至少 5 次双向占据转移、两种状态各至少 20 帧。
- 时间尺度需至少达到对应滞后时间的 2 倍，平台相对范围不超过 0.2。
- Chapman–Kolmogorov（CK）检查使用留一重复：其余重复估计基准转移矩阵，预测 1、2、4、10 倍滞后，再与留出重复的观测矩阵比较。每个状态计数足够且最大概率差不超过 0.1 才通过这一筛查。

隐含时间尺度按正的非平凡特征值计算。未采到某个状态、未连通、负或不可分辨的特征值均明确记录，不补伪计数制造转移。软件测试包含可通过诊断的已知 Markov 链以及零转移、缺失状态等反例。

这些是占据状态诊断。即使通过，也尚未验证单分子的体相、通道和位点状态划分，不发布 TPT 通量或可靠输运速率。报告同时保留各重复的前后半段与分块分子数；三个随机速度重复共享平衡起始结构的事实保留在报告中。

时间尺度定义与 CK 关系参见 [deeptime 时间尺度文档](https://deeptime-ml.github.io/latest/api/generated/deeptime.markov.tools.analysis.timescales.html)和 [CK 检查文档](https://deeptime-ml.github.io/latest/api/generated/deeptime.util.validation.ck_test.html)。周期边界距离处理参见 [MDAnalysis 2.9 距离计算](https://docs.mdanalysis.org/2.9.0/_modules/MDAnalysis/lib/distances.html)。本项目的数值筛查阈值由上述协议单独给出。

## 任务与恢复

命令行和网页使用同一任务执行入口：

```text
python -m bur01_structmine.cli mechanism assess --executor autodl --project <项目编号> --spec assessment.json
```

输入示例见 `configs/unified/assessment.example.json`。远端路径须位于本机服务器配置所指定的部署目录内。轨迹和占据矩阵留在远端，JSON 与 CSV 结果自动回传。

任务在读取时核对冻结批次、拓扑、轨迹、原分析及质检报告的校验值。每完成一个采样帧便保存检查点。中断后按原任务编号重试，复用已完成帧；协议、代码、输入或数值环境变化时拒绝直接沿用该检查点。分析执行完毕与机制采样充分性分别表示。

## 平台验收

```text
python -m bur01_structmine.cli acceptance --project <项目编号> --output <新验收目录> --ui-evidence <网页检查JSON> --recovery-evidence <恢复检查JSON>
```

验收检查家族配置与参考文件、构建与反应记录、结构复核、预测报告、模型索引、生产轨迹与质检、通道及采样报告绑定、历史文件、实验回填接口、网页与远端恢复。

实验回填检查在独立临时索引中执行，使用明确标记的软件测试记录；未测值和模拟值均不能进入实测训练输入。报告单独列出研究项目中实际存在的实测记录数量。工程检查通过、模型准确性、完整 NR 验收和机制结论不合并成一个通过状态。

报告是指定时点的快照，保留依据文件的校验值。代码、数据和环境变动后应重新验收。网页检查应实际覆盖全部页面、筛选和下载，不能只检查文件存在。
